# Ask My Docs (Python)

A local RAG-style Q&A app. Upload PDFs/TXT/Markdown (or paste a web page URL), ask questions in plain English, and get answers with source citations (document name + page number). Works in **two modes**:

| Mode | Needs `OPENROUTER_API_KEY` | Behavior |
|------|---------------------------|----------|
| **Embeddings + LLM** | ✅ | Chunks are embedded (semantic similarity), the best matches are validated, and a grounded answer with `[N]` citations is generated by an LLM. |
| **TF-IDF (offline)** | ❌ | Pure-Python keyword retrieval + template answers. No external calls, no API key required. |

If the API key is set but an embedding/LLM call fails, the app automatically falls back to TF-IDF.

## Setup (before first start)

### 1. Prerequisites

- Python **3.10+**
- (Recommended) An OpenRouter API key from <https://openrouter.ai/keys> for the embeddings + LLM mode

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Configure environment (`.env`)

Create your `.env` file from the template:

```powershell
Copy-Item .env.example .env
```

Edit `.env` and set at least `OPENROUTER_API_KEY` (leave it empty for offline TF-IDF mode):

```env
OPENROUTER_API_KEY=sk-or-v1-...
```

| Variable | Required | Default | Purpose |
|----------|----------|---------|---------|
| `OPENROUTER_API_KEY` | for AI mode | *(empty)* | Enables embeddings + LLM answers |
| `SECRET_KEY` | optional | `ask-my-docs-secret-2026` | Signs session cookies — **change for production** |
| `LLM_MODEL` | optional | `deepseek/deepseek-chat` | Answer-generation model (OpenRouter id) |
| `EMBED_MODEL` | optional | `openai/text-embedding-3-small` | Embedding model (OpenRouter id) |
| `EMBED_MIN_SCORE` | optional | `0.30` | Minimum similarity for a chunk to count as relevant |
| `PORT` | optional | `5000` | HTTP port |
| `APP_DEBUG` | optional | `0` | `1/true/yes` → Flask debug reloader instead of waitress |

> The `.env` file is gitignored — never commit your API key.

## How to Start

```bash
python app.py
```

The server starts at **http://localhost:5000** and prints its mode:

```
🚀 Ask My Docs is running → http://localhost:5000
   Mode: embeddings + LLM          (or "TF-IDF (offline fallback)")
```

### Start on a different port

```powershell
$env:PORT = 8080; python app.py
```

### Use the app

1. Open **http://localhost:5000**
2. Drop a PDF/TXT/MD into the sidebar (or click to browse)
3. Pick a chunking mode — **Structured** is best for headings/Q&A docs, **256/128** for finer-grained matching
4. Click **Upload & Index** (each PDF gets a **↗** button that opens it in a new tab)
5. Type a question and press Enter — you get an answer plus source cards with page + match score

## How to Stop

If you started it **in the foreground** (current terminal), just press **Ctrl+C**.

If it's running in the background / another window, find the process on the port and kill it:

**Windows (PowerShell):**
```powershell
Get-NetTCPConnection -LocalPort 5000 -State Listen | Select-Object -ExpandProperty OwningProcess
Stop-Process -Id <PID> -Force
```

**Windows (CMD):**
```cmd
netstat -ano | findstr :5000
taskkill /F /PID <PID>
```

**macOS / Linux:**
```bash
lsof -i :5000
kill <PID>
```

## How the Flow Works

```
                    ┌──────────────────────────────────────────────────────┐
                    │  BROWSER  (templates/index.html)                    │
                    └───────────────┬──────────────────────────────────────┘
                                    │
   ┌────────────────────────────────┼──────────────────────────────────────┐
   │ POST /upload                   │ POST /load-url                       │
   │ (PDF/TXT/MD files)             │ (web page URL)                       │
   └───────────────┬────────────────┴──────────────┬───────────────────────┘
                   ▼                               ▼
        Save file to temp uploads/{uuid}_{name}        Fetch + extract text
        hash-check (dedupe per session)                (HTML → clean text)
                   │                               │
                   └───────────────┬───────────────┘
                                   ▼
                    1 · TEXT EXTRACTION
                       PDF  → PyMuPDF, page-by-page   (extract_pdf_pages)
                       TXT/MD → sections on blank lines (extract_txt_pages)
                                   ▼
                    2 · CHUNKING  (chunk_text)
                       ├─ structured → headings / code / table blocks,
                       │   merge <40-word, split >300-word at sentences (structured_chunk)
                       └─ fixed 128/256/512 → overlapping word windows (fixed_chunk)
                                   ▼
                    3 · INDEXING  (VectorStore)
                       ├─ embeddings mode → embed_texts (OpenRouter) → cosine
                       │   index stored in vectorstore/{sid}.pkl
                       └─ TF-IDF mode → store chunks with empty vectors
                                   ▼
                    4 · RETAIN FILE (only if indexing succeeded)
                       move to uploads/{sid}__{doc_id}.{ext}
                       register in uploads/{sid}.manifest.json
                       mark document openable → "↗ open in new tab" button
                       (failed/empty/duplicate files are deleted, not retained)
                                   ▼
                    5 · RETRIEVAL  (on /ask)
                       question → vectorized
                       ├─ embeddings: cosine → top-5 above EMBED_MIN_SCORE
                       │   → validate_context
                       └─ TF-IDF:     cosine → top-4 above 0.05
                                   ▼
                    6 · ANSWER  (on /ask)
                       ├─ embeddings mode → LLM grounded answer with [N] citations
                       │   ("I don't know" when context is insufficient)
                       └─ TF-IDF mode → sentence-overlap synthesis (synthesize_answer)
                                   ▼
                    JSON → source cards (filename, page, score, section)
```

### Open a PDF in a new tab

After an upload succeeds, the sidebar doc list shows an **"Open ↗"** button next to each retained document — the **↗** is an "open in new tab" arrow, and the word **Open** tells the user what it does:

- **Open ↗** = *open this document in a new tab*.
- The button only appears for documents that were actually indexed (`openable: true`); failed/duplicate/empty files never get one.
- Clicking it navigates to `GET /file/<doc_id>` (`serve_file`), which opens an **HTML viewer page** (templates/view.html) in a new tab:
  - a header bar that clearly says **"Open document"** plus the filename and an **Open ↗** action,
  - the PDF itself embedded below the header, streamed from `GET /file/<doc_id>/raw` with `Content-Disposition: inline`.
- The file is served only to the same browser session that uploaded it (`SESSION_FILES` + manifest), so the link returns 404 after the session expires or is cleared.

### The stages

1. **Upload / Load** — `POST /upload` accepts PDF/TXT/MD (multipart), `POST /load-url` accepts a web URL. Each file is saved to a temp path and hash-checked so the same file isn't indexed twice per session.
2. **Extraction** — PDFs read page-by-page with PyMuPDF; text files split into logical sections. Empty/corrupt docs are skipped, not crashed on.
3. **Chunking** — the important part for retrieval quality:
   - **Structured**: parses Markdown headings, code fences, and table rows into semantic blocks; merges blocks under 40 words, splits blocks over 300 words at sentence boundaries. Each chunk carries `page`, `section`, `block_type`, `filename`.
   - **Fixed**: sliding word windows with 20% overlap (e.g. 256-word chunks stepped by 205 words). Smaller chunks → more granular matching; larger → more context per hit.
4. **Indexing** — chunks are added to the session's `VectorStore` (persisted to `vectorstore/{sid}.pkl`). In embeddings mode the chunk text is vectorized via OpenRouter first.
5. **Retain file** — only if indexing succeeded is the file moved to `uploads/{sid}__{doc_id}.{ext}`, registered in the session manifest, and marked `openable`. Failed/empty/duplicate files are deleted instead, so a `↗` link only ever appears for documents that were actually indexed. The manifest (`uploads/{sid}.manifest.json`) lets the app re-discover these files after a server restart.
6. **Answer** — on `POST /ask`, retrieval runs:
   - **Embeddings mode**: OpenRouter embeddings give **semantic** matching (meaning, not just keywords); the top-5 chunks above `EMBED_MIN_SCORE` are validated (`validate_context`) before use, then the LLM writes a grounded answer with `[N]` citations — or exactly *"I don't know"* if the excerpts are insufficient.
   - **TF-IDF mode**: pure-Python sparse `{term: tf·idf}` vectors + cosine similarity, stopwords removed, `CONFIDENCE_THRESHOLD = 0.05` filters weak matches; top sentences are stitched into the answer.

## API Reference

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/`            | GET  | Serve the UI |
| `/upload`      | POST | Accept files + `chunk_mode`, index them, retain originals |
| `/load-url`    | POST | Accept a web URL + `chunk_mode`, fetch + index the page |
| `/ask`         | POST | `{ "query": "..." }` → answer + sources |
| `/file/<doc_id>` | GET | Open the HTML viewer page for an uploaded document |
| `/file/<doc_id>/raw` | GET | Stream the raw PDF bytes (used by the viewer; also opens the PDF directly in a new tab) |
| `/clear`       | POST | Wipe current session's docs, chunks, and retained files |
| `/status`      | GET  | Chunk/doc counts + openable flags for the current session |

## Sessions & Storage

- Each browser tab gets a **session** via a signed cookie; documents are private to that session.
- Chunks + vectors persist to `vectorstore/{sid}.pkl`; uploaded files persist in `uploads/` and are tracked by `uploads/{sid}.manifest.json` (survives restarts).
- Sessions expire after **1 hour** of inactivity; a maximum of **20 sessions** are kept. On expiry/clear, both the vectorstore file and the retained uploads are deleted.

## Notes & Limitations

- **Two modes**: without `OPENROUTER_API_KEY` you get keyword-only answers; with the key you get semantic retrieval + LLM-grounded answers.
- **Embedding mode is online** — it needs network access to `openrouter.ai`; failures fall back to TF-IDF automatically.
- **Dev server only** — served by `waitress` on `127.0.0.1` by default. Don't expose it publicly without changing `SECRET_KEY`.
- **Stored files are session-scoped** — `/file/<doc_id>` only serves documents uploaded in the same browser session.
- **Structured parser drops tiny blocks (≤4 words)** — very short lines/tables may not be indexed.
- In **TF-IDF mode** answers are keyword-based, so paraphrased questions may score lower.
